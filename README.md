# Mortality Coding Research

Единый научный архив по истории и современной организации учета, кодирования, выбора и экспертного контроля причин смерти в России.

## Как работаем

**Пользователь загружает новые материалы только в `00_INBOX/`.** Сортировать, переименовывать и распределять источники по разделам не требуется.

Дальнейшая обработка архива выполняется по следующему принципу:

1. определить тип, период, автора и научную функцию источника;
2. перенести материал из `00_INBOX/` в тематический раздел;
3. сохранить происхождение и исходное имя в `INDEX/sources.md`;
4. для значимых источников зафиксировать, что именно они подтверждают и чего не подтверждают;
5. обновить хронологию, карту доказательств и перечень нерешенных вопросов;
6. не удалять источник без явного решения — история Git должна позволять восстановить исходное состояние.

## Структура

- `00_INBOX/` — единственное место для новых загрузок;
- `01_HISTORY/` — исторические источники и ранние формы;
- `02_NORMATIVE_USSR/` — нормативные акты СССР;
- `03_NORMATIVE_RUSSIA/` — нормативные и методические документы РФ;
- `04_ICD_WHO/` — МКБ, материалы ВОЗ, обновления, SP/M;
- `05_RESEARCH/` — научные публикации, диссертации, авторские исследования;
- `06_EXPERT_CONTROL/` — методики и исследования экспертного контроля;
- `07_AUTOMATION/` — автоматизированное кодирование и выбор причин смерти;
- `08_DIGITAL_INFRASTRUCTURE/` — ФРМСС, ЕГР ЗАГС, центры кодирования и цифровые контуры;
- `09_CURRENT_ARTICLE/` — материалы текущей статьи;
- `10_FUTURE_ARTICLES/` — материалы последующих статей;
- `INDEX/` — научный индекс всего архива.

## Принцип доказательности

Источник учитывается не только библиографически. Для ключевых документов отдельно фиксируются:

**тезис → источник → точное место → что подтверждается → ограничения интерпретации.**

Это необходимо, чтобы не смешивать наличие формы с наличием методики, издание правила с фактическим внедрением, региональное исследование с общероссийской оценкой и международную рекомендацию с ее нормативным статусом в России.

## Резервирование

История Git является первым уровнем восстановления. Дополнительно настроены автоматические снимки репозитория через GitHub Actions. Независимая внешняя копия хранится отдельно; порядок резервирования описан в `BACKUP.md`.
