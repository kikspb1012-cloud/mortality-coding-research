# Резервное копирование

Архив должен иметь несколько уровней восстановления.

## 1. История Git

Каждое изменение фиксируется коммитом. Это позволяет восстановить удаленный или замененный файл и проследить историю сортировки.

## 2. Автоматический снимок GitHub Actions

Workflow `.github/workflows/repository-snapshot.yml` ежедневно создает два файла:

- **Git bundle** — полный переносимый снимок Git-истории;
- **tar.gz** — снимок текущего содержимого репозитория без каталога `.git`.

Снимки хранятся как GitHub Actions artifacts с ограниченным сроком хранения. Это дополнительная копия, но она находится на той же платформе и поэтому не считается независимым резервом.

## 3. Независимая внешняя копия

Для независимого резервирования создано отдельное хранилище Google Drive **«Cause of Death Research — BACKUP»** с разделами `snapshots` и `manifests`.

После перевода репозитория в приватный режим будет настроена регулярная передача контрольных снимков в это хранилище.

## Правило

Резервная копия не заменяет научный индекс. `INDEX/sources.md` и `INDEX/evidence_map.md` должны позволять понять не только какой файл сохранен, но и какую доказательную функцию он выполняет.
